# Similarity companion data dictionary and reproduction guide

This companion describes resemblance and dependence in retained representations. It preserves 30 admitted relationships, 16 biological query identities, 11 complete relationships, two partial diagnostics and 17 input-incomplete relationships. The [report](../evaluation/similarity-independence-v1.md) states the findings; the [protocol](../../protocol/similarity-independence-v1.md) defines the parameters. Neither similarity nor absence of a computed edge validates a biological link or establishes independence.

All result files are under `data/processed/similarity-independence-v1/`. The [manifest](../../data/processed/similarity-independence-v1/manifest.json) records exact input/output SHA-256 values, software versions and parameters. TSV files have one header row and UTF-8 text. Empty numerical fields mean unavailable, never zero. Literal status and reason fields govern eligibility. IDs are opaque strings, including pipes and colons; never split a query ID on punctuation. `relationship_id` joins to the authoritative evidence ledger and readiness view. Paired suffixes `_a` and `_b` identify endpoints, not direction of a biological relation. Pair tables contain unordered non-self pairs once; do not sum a mirrored matrix as additional evidence.

## Representations and chemical pairs

`representations.tsv` links relationship/query/member IDs to representation kind, exact source path and hash, boundaries or identifier, completeness, status and evidence locator. `structures.tsv` accounts for all 30 relationships. Only five rows have supported machine-readable connectivity structures. `structure_id` joins to `chemical-pairs.tsv`; `alternative_set` retains an unresolved or alternative assignment without silently selecting a structure. `mapping_status`, `mapping_rationale`, `reviewer` and `reason` preserve the scope and attribution of the mapping. The reviewer field does not imply completed accountable human review.

`original_text` preserves the supplied structure. `canonical_isomeric_smiles` and `computed_inchikey` are derived encodings; `source_inchikey` is the source value and `connectivity_key` is its connectivity layer. `formula` is calculated, with independent verification recorded separately in `formula_check`. `stereochemistry` and `chiral_sensitivity_eligible` constrain interpretation: chiral sensitivity is withheld pending source reconciliation. `structure-mapping-attempts.tsv` retains aliases, candidate records, source packet, disposition and search scope for supported and unavailable cases.

`chemical-pairs.tsv` accounts for all 435 relationship pairs. Ten pairs among five structures have numerical `tanimoto` values; 425 are unavailable. `fingerprint` and `scenario` identify the declared representation and calculation. `exact_isomeric_equal` records canonical isomeric equality separately from a fingerprint score of one. `range_min`/`range_max` describe eligible alternative-member pair ranges; unavailable alternatives do not receive invented ranges. `flag_0_7` and `flag_0_9` mark prespecified descriptive Tanimoto cutoffs, not pathway-family assignments. The heatmap has an unavailable state distinct from zero; its diagonal is a display convention, not 30 measured self-comparisons.

## Protein and locus tables

`gcf-members.tsv` records all 79 displayed members of seven selected families, including source archive member, member-byte hash, completeness and protein count. `proteins.tsv` contains their 1,209 displayed proteins. `anchor-members.tsv` and `anchor-proteins.tsv` add ten accepted locus/construct/CDS anchors and 43 annotated proteins. `member_id`, `protein_id` and `family` join these tables to pair records; `source_labels`, `source_protein_id`, `source_path` and `source_locator` preserve origin. `sequence` is the retained amino-acid sequence, `sequence_sha256` hashes its encoding, `length` counts residues and `order` preserves display/annotation order. Anchor `bounds_0based_halfopen` is a zero-based half-open interval in the named source record. `representation_scope` and `member_kind` distinguish source-displayed members, complete or partial intervals, constructs and single CDS. These are not interchangeable biological units.

`genomic-eligibility.tsv` records source-annotated role eligibility. `genomic-pairs.tsv` contains GCF-member core pairs; `anchor-genomic-pairs.tsv` adds pairs involving accepted anchors. `all-genomic-pairs.tsv` combines them and is the final table for the 10,516 cross-member core records, of which 3,575 have compatible roles and numerical alignments. Incompatible roles have null metrics and explicit reasons. Do not concatenate the combined and component tables. `reused-correspondence.tsv` retains earlier correspondence evidence under its original method/scope; `rejected-sequence-search-candidates.tsv` preserves rejected candidates, not accepted matches. `hash_scope` identifies what the retained hash covers.

For alignment records, `identical` counts equal residues in paired nongap positions and `paired` counts paired nongap positions. `identity = identical/paired`; `coverage_a = paired/length_a` and likewise for endpoint b. Scores use global BLOSUM62 with opening −10 and extension −0.5, including terminal gaps. `optimal_alignment_paths` counts optimal paths; the first library path determines the retained alignment. `exact_equal` compares full sequences, while the sequence hash fields identify the endpoints. `qualifies_70_80` and `qualifies_90_80` require identity at least 70% or 90% and coverage at least 80% on both sides. `reciprocal_best_tie` preserves tied reciprocal-best matches. These screens do not establish orthology or common products.

`genomic-locus-pairs.tsv` describes GCF member pairs; `all-genomic-locus-pairs.tsv` includes anchors. The all-genomic table is the final combined view. `compatible_core_pairs` is the number of compatible core comparisons. `annotated_proteins_a/b` (or `all_annotated_proteins_a/b` in the component table) counts all represented annotated proteins. `annotated_fraction_a_70`, `_b_70`, `_a_90` and `_b_90` divide distinct qualifying reciprocal core matches by the corresponding total annotated count. These fractions are lower bounds because unclassified and non-core proteins are not numerically compared. `reciprocal_order_pairs_70/90` carries paired gene-order positions, not an independent synteny score. `genomic-family-summary.tsv` gives within/between-family identity extrema/medians, compatible-pair and represented-member-pair counts, threshold counts and exact duplicate counts. Its `scope` prevents extrapolation to unrepresented clusters.

## Spectra and acquisition provenance

`spectra.tsv` records 382 retained joined exports: 91 Trichoderma and 291 black yeast. `spectrum_id`, `feature_id` and `pool` retain the native-export-to-feature join; feature IDs are pool-local. `precursor_mz` is mass-to-charge, `rt_seconds` is retention time in seconds and `charge`/`polarity` describe exported ion state. `polarity_source` preserves its evidence. Collision-energy values have unrecorded units; unknown instrument values stay unknown. `peaks_before/after` bracket the frozen filtering and `canonical_original_peaks_sha256` hashes the canonical unprocessed peak list. `native_scan` preserves the selected scan identifier.

`spectral-pairs.tsv` accounts for all 72,771 pairs among these spectra. Its 46,290 numerical pairs are within pool (4,095 Trichoderma and 42,195 black yeast). The 26,481 cross-pool pairs are excluded for opposite export charge signs. `cosine` is CosineHungarian at 0.02 Da on square-root transformed, L2-normalized intensities after the protocol's filtering. `matched_peaks` is the matched-peak count. `flag_0_7_6peaks` and `flag_0_9_6peaks` require both the named cosine threshold and at least six matched peaks; 93 and 51 pairs qualify. `metadata_stratum`, endpoint peak counts and collision-energy values bound comparison. `exact_peak_list_equal`, `exact_native_scan_equal` and `shared_native_event_count` describe distinct kinds of duplication. High cosine is resemblance, not a chemical assignment.

`spectral-provenance.tsv` links each exported spectrum to `native_events`, their count, collision-energy values, the selected export event and its source. `collision_energy_unit`, `instrument`, `source_path` and `scope` preserve missing metadata and acquisition limits. Seven Trichoderma and 958 black-yeast candidate spectra are not represented. No table creates native joins for historical Caesar features.

## Dependence and exposure

`dependence-edges.tsv` records typed endpoints in an explicit namespace. `edge_id` is the join to grouping scenarios; `edge_type`, `source`, `certainty`, `rule_version`, `grouping_applicability` and `reason` state why an edge exists. Shared query, curated pathway, construct/host context, source design, exact sequence and spectral resemblance are different edge types. Eight valactamides share one query, four benzomalvins share another, and three AtFAC9J20 loci share a construct/host context without becoming one pathway.

`group-scenarios.tsv` has one row per relationship per scenario. `edge_rules` prints eligible merger rules, `merger_edges` identifies supporting edges and `unresolved_edges` preserves uncertainty. `group_id` is scenario-local. `counts`, `query_id`, `pathway_group`, `input_state`, `parent_frozen_group`, `split_feasibility` and `reason` retain the grouping denominators and limits. `not_adjudicated` is not evidence for a distinct or shared pathway. `group-summary.tsv` counts scenario components and those with complete relationships separately. The conservative scenario has five components but only one containing complete relationships. `authoritative_complete_analysis_groups` remains one and `holdout_established` remains false. The scenarios do not replace frozen groups or establish independent replicates.

`exposure.tsv` is keyed by relationship, method/run and method layer. It distinguishes retrospective source selection, declared public-reference membership and weight-specific training membership. Method/upstream versions, execution scope, asset version and hash, searched universe, roster completeness and matching rule qualify every status. `confirmed_overlap` means a match under the printed rule; `no_match_in_declared_complete_roster` and `partial_roster_no_match` describe only their named search universe. Neither means unexposed. `unknown` preserves absent evidence and `not_applicable` marks inapplicable layers. The five supported structure crosswalks permit bounded stable-ID reference checks; complete class-table files are not complete training rosters. Rosetta mapping is context only, with no executed Rosetta comparison. Spec2Class weight-specific training membership remains unknown.

`executed-model-assets.tsv` records asset hashes from actual execution receipts, `source_run` and `hash_basis`. These rows identify consumed assets without bundling weights or claiming verified training rosters. Deterministic controls have no learned training assets but remain retrospectively exposed. `summary.json` summarizes counts; the tables and frozen manifest retain the more detailed scope.

## Reproduction boundary and private packaging

Candidate v3 inherits all v2 scientific payloads byte for byte and adds this companion. The [input-disposition table](../../data/manifests/similarity-input-disposition-v1.tsv) lists every manifest-consumed input, exact path, bytes, SHA-256, package disposition and role. All 76 consumed inputs are bundled at those paths. The three analysis scripts, protocol, declared plan, stage receipts, parameters, alignment caches/settings, environment/install receipts and completed result tables accompany them. Historical absolute commands and machine paths remain provenance; the root-relative commands below describe the scientific stages and were not rerun during integration.

```text
python scripts/similarity_independence.py --stage all
python -m scripts.similarity_locus_anchors
python -m scripts.finalize_similarity_independence
```

Run only in a separate extracted working copy after restoring the recorded Python environment and reviewing the frozen settings. These commands write result files and stage receipts. Caches require matching settings and sequence hashes. `manifest.json` records observed Python/package versions and package RECORD hashes; the retained install receipt records resolved wheels. A package RECORD hash is not a portable environment lock or proof that dependencies were reinstalled. Predictor weights and raw LC-MS files are not needed to inspect these saved similarity outputs or run these stages, which consume exported spectra and model execution receipts rather than repeating inference. Raw-to-export reconstruction remains a separate historical workflow with its own retrieval dependencies.

Integration checks verify outer membership, every payload hash and inherited-byte preservation. Prior core/spectral/phylogeny replay evidence applies to unchanged inherited science. No new clean extraction replay of the similarity calculations, human chemical review, anonymous download route or public release is claimed. Missing representations and exact training membership remain unresolved.
